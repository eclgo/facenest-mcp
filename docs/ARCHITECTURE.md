# Architecture

One page: what the adapter is, what it touches, and which document owns which fact.
Verified against the code on 2026-11-21; where a number matters, this page points at the file
that enforces it instead of repeating it.

## The shape

```
AI client (Claude Desktop / Cursor / OpenCode / Codex / DSH …)
        │  MCP over stdio  (tools/list, tools/call)
        ▼
facenest-mcp adapter  —  Python, standard library only
        │  HTTP to 127.0.0.1  (token from mcp_endpoint.json)
        ▼
FaceNest app  —  the library, the models, the database, the quotas
```

Nothing leaves the machine. The adapter makes no network calls except to the loopback address of
the running app, and the app answers only on loopback.

## What each part does

| Part | File | Job |
|---|---|---|
| MCP server + tool registry | `facenest_mcp/server.py` | Speaks MCP on stdio, holds `TOOLS` (the tool list: names, parameters, descriptions) and `AGENT_PROMPT` (the system prompt), implements the CLI (`--selftest`, `--list-tools`, `--agent-prompt`, `--call`) |
| App API client | `facenest_mcp/api.py` | Calls the app's local HTTP endpoints, resolves the endpoint, re-reads it on every call so a port/token change after an app restart is picked up |
| Endpoint resolution | `facenest_mcp/endpoint.py` | Finds `mcp_endpoint.json` (explicit `--endpoint`, then `FACENEST_ENDPOINT`, then the usual locations) |
| Error catalogue | `facenest_mcp/errors.py` | Every `ERR_…` code with its meaning, the next step, and whether to retry |
| App side (not this repo) | a copy shipped inside the FaceNest app | The adapter travels with the app; the FaceNest side keeps that copy in step with this repository through its own sync and verification scripts. The app also enforces session quotas and the two switches |

## One source for every number

The tool descriptions in `server.py` are the single place where parameters and limits are
written. Everything derived from them is generated and gated:

| Page | Generated by | Gate |
|---|---|---|
| `docs/_generated/_tools.txt` (compact listing) | `scripts/_dump_tools.py` | file == `render(TOOLS)` |
| [TOOLS.md](TOOLS.md) (parameters, required flags, read/write, quotas) | `scripts/gen_tools_doc.py` | file == `render(TOOLS)`; group map must cover exactly the tools the code exposes |
| README tool table, tool/scenario/error-code counts | hand-written, **counted by the gate** | `tests/test_docs.py` compares each claimed number with `len(TOOLS)`, `len(errors.HINTS)` and the numbered rows of [TESTING.md](TESTING.md) |
| Agent guides' system prompt | copied from `AGENT_PROMPT` | both guides must contain it verbatim |
| Guide contents blocks | `scripts/gen_doc_toc.py` | entries == the file's own `## ` headings |

A number that is typed by hand in a prose page is the one number allowed to drift. That is why
quotas live in tool descriptions, and prose pages link to [TOOLS.md](TOOLS.md) instead of
repeating them.

## Read/write and the two switches

- The app has two independent switches: **Expose the MCP service** (connect at all) and
  **Allow writes** (let the write tools change anything). Read tools never write.
- Which tools are write tools is derived from their own descriptions in `server.py`, and the
  resulting set matches the app-side write gates (`_guard(..., require_write=True)` in
  `App/app/api/routes_mcp.py`). The label is printed in [TOOLS.md](TOOLS.md).
- Quotas are enforced by the app per call and per session; the counters appear in tool replies
  (`usage: "n/cap"`).

## Tests and CI

```bash
python -m unittest discover -s tests     # protocol, error text, documentation gates - no app needed
python tests/e2e_stdio.py <mcp_endpoint.json>   # end-to-end against a fixture, not your library
```

The documentation gate (`tests/test_docs.py`) exists because the docs are the only world
knowledge a model has, so "the docs contain every tool / every error code / the right
counts" is an executable assertion, not a review habit. CI
([`.github/workflows/test.yml`](../.github/workflows/test.yml)) runs the same suite on
Python 3.9 / 3.12 / 3.13 on every push, and uploads no artifacts.

## What is open source

The adapter in this repository. The app — the library, the models, the database — stays closed;
it is what the adapter talks to over loopback.
